# TypeTwice

SNS を開く前に、Monkeytype 風の画面で英文を 1 行タイプしてもらうブラウザ拡張です（Chrome / Brave、Manifest V3）。

無意識に SNS を開いたとき、そこで一度手を止めて「本当に見るか」を考え直すきっかけを作ります。英文はプレーンテキストに 1 行 1 文で書いておくだけで追加でき、コードを変更する必要はありません。

- 対象サイトを開くと、元のページは残したまま不透明な全画面ゲートで覆います。
- 英文を正確に入力し、最低所要時間（初期値 20 秒）が過ぎると「Open anyway · 5 min」を押せるようになります。
- 開いたあとは、そのサイトのすべてのタブで実時間 5 分間（初期値）ゲートが出ません。
- 「Go back」はいつでも押せます。
- データはすべて端末内に保存されます。サーバー、アカウント、外部 API はありません。

## セットアップとビルド

Node.js（v24 以降を推奨。v26 で確認済み）と npm を使います。

```sh
npm install
npm run build        # dist/ に読み込み可能な拡張を生成
```

`npm run build` は、同梱の `public/messages.en.txt` を拡張本体と同じパーサーで検証します。不正な行があればビルドは失敗するため、壊れた文章ファイルが出荷されることはありません。

## Chrome / Brave への導入

1. `chrome://extensions`（Brave では `brave://extensions`）を開きます。
2. 右上の「デベロッパーモード」をオンにします。
3. 「パッケージ化されていない拡張機能を読み込む」から `dist/` フォルダを選びます。
4. 初回は設定画面が自動で開きます。X と Instagram が候補として表示されるので、保護したいサイトのスイッチをオンにします。そのときブラウザがサイトへのアクセス許可を求めるので、許可してください。

コードや文章ファイルを変更したら、`npm run build` を実行し、`chrome://extensions` で拡張の再読み込みボタンを押します。

## 使い方

対象サイトを開くと、次の流れになります。

1. 解除状態を確認する間は、不透明な待機画面で覆います。確認が速ければ、何も見えないうちに終わります。
2. 解除期限内ならそのままページを表示します。期限外なら英文を 1 行出題します。
3. 最初の 1 文字を入力した時点から、最低所要時間を計測します。
4. 全文が一致し、かつ最低所要時間を満たすと「Open anyway · 5 min」が押せるようになります。ボタンを押すか Enter で開きます。入力が終わっただけでは開きません。

入力ルール:

- 大文字・小文字、スペース、句読点は厳密に比較します。誤入力は残り、Backspace、選択範囲の置換、Undo/Redo、矢印キーなど通常の編集で直せます。
- 貼り付けとドロップはできません（ページ全体のコピー・貼り付けには影響しません）。
- タイマーが進むのは、ゲートが表示され、タブとウィンドウがアクティブで、入力欄にフォーカスがある間だけです。ボタンや別のタブ・アプリに移ると止まり、入力欄に戻ると再開します。
- スリープなど 1.5 秒以上のタイマー中断は加算しません。
- 誤入力をしても、全リセットなどの罰則はありません。

「Go back」を押すと、ブラウザの履歴を 1 つ戻ります。戻る先がない場合は「You can close this tab.」と表示し、元のページは表示しません。戻った先が同じ SNS なら、そこでもゲートが出ます。

## 英文 TXT の書き方

ファイルは `public/messages.en.txt`（同梱用）、または設定画面からインポートする任意の `.txt` ファイルです。

```text
I am just checking one thing. That is what I said last time.
The algorithm has a plan for my afternoon. I apparently do not.
I could close this tab right now, but first I will finish this sentence.
```

- 文字コードは UTF-8 です（BOM 付きも可）。ファイル上の 1 行が 1 課題になります。長い文章も 1 行に書いてください（エディタの折り返し表示は問題ありません）。
- 改行は LF、CRLF、単独の CR のどれでも構いません。空行は無視します。
- 1 行に複数の文を書いた場合、その行全体が 1 課題です。
- コメント構文やエスケープはありません。`#` で始まる行も、`\n` という 2 文字も、そのまま入力対象になります。
- 次の文字だけは自動で変換し、変換した行数をプレビューに表示します。

  | 入力 | 変換後 |
  | --- | --- |
  | ‘ ’（U+2018 / U+2019） | `'` |
  | “ ”（U+201C / U+201D） | `"` |
  | …（U+2026） | `...` |
  | – —（U+2013 / U+2014） | `-` |
  | ノーブレークスペース（U+00A0）、全角スペース（U+3000） | 半角スペース |

- 連続するスペースとタブは 1 つの半角スペースにし、行頭・行末の空白は取り除きます。
- 変換後に ASCII の印字可能文字（U+0020〜U+007E）以外が残る行はエラーです。ゼロ幅文字、行の途中の BOM、絵文字、日本語、アクセント付き文字などが該当します。英語かどうかの判定は行いません。
- 正規化後に完全に同じ行は 1 つにまとめます（大文字・小文字は区別します）。まとめた件数はプレビューに表示します。

上限:

| 項目 | 上限 |
| --- | --- |
| ファイルサイズ | 1 MiB（1,048,576 bytes） |
| 1 行の長さ | 正規化後 2,000 文字 |
| 行数 | 空行を除き、重複除去前で 5,000 行 |

不正な行が 1 行でもあれば、ファイル全体を取り込みません。その場合でも、今使っている文章集はそのまま残ります。エラーには元のファイルの行番号、問題の文字、コードポイントを表示します。例:

```text
Line 12: unsupported character U+200B (zero-width space) at column 8.
Line 3: invalid UTF-8 byte 0xFF at byte 28. Save the file as UTF-8 and try again.
```

### 文章を追加・差し替える

**同梱の文章（開発者向け）**
本番用の英文は `public/messages.en.txt` に書きます（今は中立的なサンプルが 3 行入っています）。行を追加してから `npm run build` を実行し、拡張を再読み込みしてください。アプリケーションのコードを変更する必要はありません。

**設定画面からのインポート（利用者向け）**
1. 設定画面の「Sentences」で「Choose a .txt file…」を押し、ファイルを選びます。
2. 件数、まとめた重複の数、変換した行数、先頭 5 件のプレビューを確認します。エラーがあれば「Replace sentences」は押せません。
3. 「Replace sentences」を押すと、文章集が置き換わります（追記ではありません）。ファイルを選んだだけでは何も変わりません。

補足:
- 行を追加したいときは、元の TXT に追記してからもう一度インポートしてください。ブラウザは元のファイルを監視していないため、編集したら再インポートが必要です。
- インポートした文章集を使っている間は、同梱の文章と混ぜません。「Restore bundled sentences」で同梱の文章集に戻せます。
- 画面に出ている課題は、出題時の文章のまま続きます。新しい文章集は次の課題から使われます。
- 出題は文章集から等確率に 1 行選びます。候補が 2 件以上あれば、同じサイトで直前に出した文章は続けて出しません。

## 設定

| 項目 | 初期値 | 範囲 |
| --- | --- | --- |
| Gate enabled（全体の有効・無効） | オン | — |
| Minimum typing time（最低所要時間） | 20 秒 | 5〜300 秒（整数） |
| Unlock time（解除時間） | 5 分 | 1〜60 分（整数） |
| Sites | X、Instagram（どちらもオフ） | 任意の HTTP/HTTPS ドメインを追加可能 |

### 解除時間（5 分）の意味

解除時間は、閲覧できる時間の厳密な上限ではありません。「次に操作したり戻ってきたりしたときに、もう一度課題を求めるための期限」です。

- 解除操作が完了した時点から、実時間で数えます。同じサイトのすべてのタブで共有します（x.com と twitter.com は同じ X として扱います）。
- 解除中にページを移動したり別のタブで開いたりしても、期限は延びません。
- 期限が切れても、見ているページを突然閉じたり再読み込みしたりはしません。次のいずれかのタイミングでゲートが出ます。
  - 別のタブ・ウィンドウ・アプリからそのタブに戻ったとき
  - 再読み込みしたとき
  - 通常のページ移動や、SPA による URL 変更（`pushState`、`popstate`、ハッシュ変更）が起きたとき
  - 戻る/進むキャッシュ（BFCache）から復帰したとき
- 再びゲートを出すときもページは残したまま覆うだけなので、書きかけの投稿や DM（textarea、contenteditable）、スクロール位置は消えません。解除後は、以前のフォーカスとキャレット位置を可能な範囲で戻します。

設定の変更は新しい課題から適用されます。画面に出ている課題は、出題時の時間設定のままです。

### サイトの追加

ドメイン（例: `reddit.com`）を入力します。URL を貼り付けた場合は、ドメインだけを取り出して結果をプレビューに表示します。先頭の `www.` は取り除きます。登録したドメインとそのサブドメインは、同じサイトとして 1 つの解除を共有します。

- `notx.com` や `x.com.evil.example` のように、文字列が似ているだけの別ホストは対象になりません。
- ユーザー情報付きの URL、ワイルドカード（`*`）、IP アドレス、単独のドメイン名（`localhost` など）、単独の公開サフィックス（`co.uk`、`github.io` など）、ブラウザ内部の URL は登録できません。公開サフィックスかどうかは `tldts` ライブラリで判定しています。
- 既存のサイトと重なるドメイン（例: X がある状態での `mobile.twitter.com`）は登録できず、どのサイトと重なっているかを表示します。

## 権限

| 権限 | 用途 |
| --- | --- |
| `storage` | 設定、文章集、統計、解除期限の保存 |
| `scripting` | 対象サイトへのコンテンツスクリプトの登録と、すでに開いているタブへの注入 |
| `optional_host_permissions: *://*/*` | 宣言のみです。実際には、サイトを有効にした操作のときに、そのサイトだけ（例: `*://*.x.com/*`）を要求します |

- サイトをオフにしたり削除したりすると、そのサイトのアクセス権限は返却し、スクリプトの登録も解除します。
- 有効化する前から開いていたタブにも、その場でゲートを注入します。注入できなかったタブがあれば、再読み込みが必要であることを設定画面に表示します。
- ブラウザの設定画面などでアクセス権限が取り消された場合は、そのサイトを「Permission required」と表示し、開いているゲートを取り除きます。「保護中」とは表示しません。
- `activeTab`、`tabs`、`webRequest`、`cookies`、`history`、`clipboardRead`、すべてのサイトへの常時アクセスは使いません。外部スクリプト、CDN、`eval` も使いません。
- `gate.html` / `gate.js` / `gate.css` は、ページにゲートを iframe として埋め込むために `web_accessible_resources` で公開しています（後述の制約を参照）。

## 状態の保存先と寿命

| データ | 保存先 | 寿命 |
| --- | --- | --- |
| 設定、インポートした文章集、日次統計 | `chrome.storage.local` | 拡張を削除するまで残ります。統計は直近 90 日分を保持します。 |
| 解除期限、発行した課題、直前の出題 | `chrome.storage.session` | Service Worker が停止しても残ります。ブラウザの再起動、拡張の再読み込み・更新で消えます（次の訪問で新しい課題になります）。 |
| 入力途中の文字列、タイマー | ゲート iframe のメモリ | そのページが開いている間だけ残ります。Service Worker の再起動では消えません。再読み込みやタブを閉じると新しい課題になります。 |

- 全体の無効化やサイトの無効化をすると、出題中のゲートも閉じ、解除期限も破棄します。もう一度有効にしたときは新しい課題になります。
- 文章集を変更しても、すでに有効な解除期限は取り消しません。
- 入力した全文、打鍵ログ、ページのタイトル、URL のパスやクエリは保存しません。console に出すエラーメッセージからも URL を取り除いています。

## 統計

ポップアップと設定画面に、今日の数を表示します。日付は端末のローカル日付です。

| 表示 | 数えるタイミング |
| --- | --- |
| Gates shown | 課題が実際に表示されたとき（課題 1 件につき 1 回）。裏で準備しただけでは数えません。 |
| Opened anyway | 解除が成立して新しい解除期限ができたとき（課題 1 件につき 1 回） |
| Chose to go back | Go back を確定したとき（課題 1 件につき 1 回） |

- 別のタブで解除されたことでゲートが消えた場合は、Opened anyway に数えません。
- 何も押さずにタブを閉じた場合も、Chose to go back には数えません。
- 「節約できた時間」のような、実際には観測していない効果は表示しません。

## 仕組み

```text
manifest.json            Manifest V3（ビルド時に package.json のバージョンを反映）
public/messages.en.txt   同梱の文章集（本番用の英文に差し替える場所）
public/icons/            ツールバー用アイコン（scripts/make-icons.ts で生成）
src/core/                UI やブラウザ API に依存しない純粋関数
  corpus-parser.ts       TXT の厳密な UTF-8 デコード、正規化、検証、重複除去
  typing.ts              文字単位の比較、進捗、解除可能かどうかの判定
  timer.ts               フォアグラウンド時間の計測（長い中断は加算しない）
  grants.ts              解除期限（延長しない、二重発行しない）
  sites.ts / domain-input.ts  ホストの照合、重なりの検出、ドメイン入力の正規化
  picker.ts / stats.ts / settings.ts / hash.ts
src/background/          Service Worker。設定、解除、課題、統計の唯一の書き込み元。更新は直列化
src/content/             コンテンツスクリプト（document_start、トップフレームのみ）
src/gate/                ゲート画面（拡張ページ。content が iframe として埋め込む）
src/popup/ src/options/  ポップアップと設定画面
src/shared/              メッセージの型、通信の補助、DOM の補助
tests/unit/              Vitest（純粋ロジックと Service Worker のロジック）
tests/e2e/               Playwright（実ブラウザ + ローカルの検証ページ）
scripts/                 ビルド、アイコン生成、プライバシーチェック
```

ゲートは二重の構造になっています。

1. **カバー**：コンテンツスクリプトが `document_start` で、`<html>` 直下に Shadow DOM の不透明な全画面要素を置きます。Popover API でトップレイヤーに出し、背後の `<body>` には `inert` を、`<html>` には `overflow: hidden` を設定します。これでクリック、Tab 移動、スクロール、ページ内検索が背後のページに届きません。解除時は、拡張が変えた値だけを元に戻します。
2. **入力画面**：カバーの中に拡張ページ（`gate.html`）を iframe として埋め込みます。打鍵は iframe 内で完結するため、サイトのキーボードショートカット（例: X の `l` で「いいね」）に届きません。また、サイトのスクリプトは入力画面を読み取ったり書き換えたりできません。

解除の要求は、iframe から Service Worker に送ります。Service Worker は、送信元タブのトップレベル URL からサイトを判定し直し、課題 ID、タブ、全文一致、所要時間の妥当性（壁時計の経過時間を超えていないか）を確認します。そのうえで直列化した処理の中で解除期限を発行します。ページ側の `postMessage` だけで解除することはできません（iframe からの合図は「Service Worker にもう一度問い合わせる」きっかけとしてしか使いません）。

## テスト

```sh
npm test                              # ユニットテスト（Vitest）
npm run typecheck                     # 型チェック
npx playwright install chromium       # 初回のみ：E2E 用の Chromium を取得
npm run test:e2e                      # ビルドしてから E2E を実行（Playwright の Chromium）
E2E_BROWSER=chrome npm run test:e2e   # インストール済みの Google Chrome で実行
E2E_BROWSER=brave npm run test:e2e    # Brave で実行（BRAVE_PATH でパスを変更可能）

npm run verify                        # typecheck + test + build + check:privacy
```

E2E テストでは、x.com、twitter.com、instagram.com、example.org などへのリクエストを、ローカルの検証ページ（`tests/e2e/fixtures/site.html`）に差し替えています。このページには、textarea、contenteditable、ショートカット、SPA 遷移が入っています。実際の SNS にはアクセスしません。

### 検証結果（2026-10-29）

ユニットテストは 101 件すべて成功しました。E2E テストは 30 件で、上の 3 ブラウザすべてで成功しています。

自動テストで確認した項目:

- **文章ファイル**：3 行の読み込み、LF / CRLF / CR / 末尾改行 / BOM、空白の正規化、記号の変換、重複除去（大文字・小文字の区別）、`#` 行と `\n` の扱い、絵文字・ゼロ幅文字・日本語・不正な UTF-8 の拒否と元の行番号、サイズ・行長・行数の境界、失敗時に既存の文章集を残すこと、インポート・復元・ブラウザ再起動後に同じ文章集であること、候補が 1 件のときの動作と直前の文章を避けること
- **入力と時間**：最低時間前は解除できない、1 文字でも違えば解除できない、余分なスペース・大文字小文字の誤りの検出、矢印キー・Delete・選択範囲の置換・Undo/Redo のあとも表示と判定が入力内容と一致すること、キーボードによる実際の貼り付けとドロップが無効であること（同じ貼り付けが通常のページでは有効であることも確認）、入力欄からフォーカスが外れると計測が止まり戻ると再開すること、長い中断を加算しないこと（ユニット）、タブを切り替えても同じ課題・入力に戻ること、入力が終わってもボタンを押すまで開かないこと、READY のあとに削除するとボタンが無効に戻ること
- **サイトと状態**：x.com と twitter.com が解除を共有し Instagram は独立していること、似た文字列の別ホストに注入しないこと、複数タブでの期限共有と同期、通常の移動で期限が延びないこと、同時解除で二重計上・期限延長が起きないこと（ユニット）、Service Worker を停止・再起動しても入力と解除が保たれること、SPA 遷移・ハッシュ変更・再読み込み・BFCache 復帰での再確認、期限切れだけでは画面を奪わないこと、再ゲートと再解除の前後で下書き・フォーカス・キャレットが残ること、背後へのクリック・スクロール・Tab 移動・キー入力が届かないこと、解除後にスタイルが残らないこと、厳しい CSP・Trusted Types・COEP のページでも動くこと
- **設定と権限**：任意サイトの追加・重複の拒否・削除、権限要求の拒否、権限の撤回と再付与、全体の無効化と再有効化、有効化より前から開いていたタブへの注入、拡張が無効化されたときの復旧画面
- **Go back**：前のページに戻ること、履歴がないときの終了画面、同じサイトの別ページに戻ったときに新しいゲートが出ること、統計（タブを閉じただけでは Chose to go back に数えないこと）

自動化の都合で、本番と異なる条件で確認した項目と、確認できていない項目:

- **権限ダイアログ**：ブラウザ自体の許可ダイアログは自動操作で押せません。そのため E2E では、ビルド済みの拡張のコピーにテスト用ホストを `host_permissions` として事前付与しています。この状態では `permissions.request` がダイアログなしで成功します。拒否は `chrome.permissions.request` をスタブに置き換えて、撤回は `chrome://extensions` のサイトアクセス設定を変更して確認しました。`dist/` の manifest は変更していません。
- **タブ・アプリの切り替え**：ヘッドレスのブラウザでは全タブが「表示中」のままなので、実際のタブ切り替えによる `visibilitychange` は再現できません。「戻ってきたとき」の再確認は `focus` イベントで代用しました。別のタブやアプリにいる間に計測しないことは、ユニットテストと実装（`visibilityState` / `hasFocus()` の確認）による担保です。
- **実際の X / Instagram**：実サイトでの表示は確認していません。サイトの DOM 構造には依存しない作りにしています。
- **確認していないもの**：実機の IME（日本語入力）での変換中の挙動（ロジックはユニットテスト済み）、スクリーンリーダーでの読み上げ、`prefers-reduced-motion` の見た目、実際のスリープからの復帰、Windows / Linux。
- **E2E の設定**：Playwright のビューポートエミュレーションを使うと、タブ切り替えのあとで iframe 下部のクリック判定がずれるヘッドレス特有の現象がありました（エミュレーションを使わない場合は発生しません）。そのため E2E は実際のウィンドウサイズで動かしています。また、Playwright が既定で無効にしている BFCache を有効にして、BFCache 復帰の経路を実際に通しています。

## 既知の制約

- これは自制を支援するための UI ゲートで、ブロッカーではありません。背後のページの読み込みや通信、スクリプトの実行は止めません。動画や音声が鳴り続けることもあります。
- 拡張の設定画面からいつでも無効化・削除できます。改変防止や削除防止の仕組みはありません。Shadow DOM や iframe も、サイト側からの改変を完全に防ぐ境界ではありません（例えば、サイトがカバー要素を削除しても再挿入はしますが、そのとき入力途中の内容は失われます）。
- サイトが自前のモーダル（`<dialog>` の `showModal()` やポップオーバー）をゲートより後に開くと、ブラウザの仕様上、そちらがトップレイヤーで手前に表示されることがあります。
- 対象はトップフレームだけです。他のサイトに iframe で埋め込まれた SNS は覆いません。
- 期限は「次の操作・復帰時に再度求める」ためのもので、同じ画面を見続けている間は追い出しません。
- ゲートの iframe（`gate.html`）は `web_accessible_resources` として全サイトに公開しているため、サイト側からこの拡張の存在を推測できます。ただし保護対象外のページに埋め込まれても、ゲートは何もしません。
- 解除状態は `chrome.storage.session` に保存しているため、ブラウザの再起動や拡張の更新で消えます（仕様どおりです）。
- 対応はデスクトップ版の Chrome と Brave だけです。Firefox、Safari、モバイルには対応していません。
